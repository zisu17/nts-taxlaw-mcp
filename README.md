# nts-taxlaw-mcp

국세청 **국세법령정보시스템**(<https://taxlaw.nts.go.kr>) 원본을 직접 조회하는 MCP 서버.
Python · FastMCP 로 구현했다.

법제처 미러(`ntsCgmExpc`)를 거치지 않고 국세청 자체 엔드포인트를 호출하기 때문에

- 최신 예규가 즉시 잡히고,
- **본문(회신·판단·결론)까지** 구조화해서 가져오고,
- 문서번호 **exact lookup** 이 가능하다.

기존 `korean-law-mcp` 는 법제처 OPEN API 특성상 국세청 해석례에 대해 목록 검색만
제공하고 본문 조회는 `[NOT_SUPPORTED]` 를 반환한다(`상세링크의 ntstDcmId는 법제처
일련번호와 다른 별도 식별자라 자동 변환 불가`). 이 MCP는 이러한 한계를 보완해 국세청 원본에서 해석례를 직접 조회하고, 문서번호 기반 검색과 상세 본문 조회를 제공한다.

## 3. 문서번호 검색

가장 중요한 기능이다. 표기가 어떻게 달라도 같은 문서로 정규화한다.

```
서면-2026-법규재산-0119        ← 정규형
서면 2026 법규재산 0119        ← 공백 구분
서면2026법규재산0119           ← 구분자 없음
서면서면-2026-법규재산-0119     ← 접두 중복
질의회신 서면-2026-법규재산-0119 ← 문서구분 라벨 붙음
질의회신서면-2026-법규재산-0119  ← 라벨이 붙어서 복사됨
국세청 서면-2026-법규재산-0119   ← 생산기관 붙음
```

관측된 문서번호 배열은 세 가지다.

| 레이아웃 | 형태 | 예 |
|---|---|---|
| A | `종류-연도-분류-일련` | `서면-2026-법규재산-0119`, `사전-2026-법규소득-0543`, `조심-2025-인-4460`, `대법원-2024-두-55396`, `헌법재판소-2011-헌바-97` |
| B | `종류-기관-연도-일련` | `적부-국세청-2026-0119`, `이의-광주청-2026-0024`, `심사-부가-2026-0018` |
| C | `기관 부서-일련` | `재정경제부 국제조세협력과-104` |

A 와 B 는 **두 번째 마디가 4자리 연도인지**로 구분한다. 이 구분이 없으면
`적부-국세청-2026-0119` 의 `국세청` 을 기관 접두로 오인해 잘라내게 된다.

### exact match 원칙

```
정확히 일치        → found: true,  exactMatch: true,  document 반환
일치 없음          → NOT_FOUND,    similarDocuments 별도 반환
```

`법규재산-0119` 처럼 일부만 겹치는 입력은 **절대 정답으로 반환하지 않는다.**

```
▶ lookup_tax_document("법규재산-0119")  → [NOT_FOUND]
   similarDocuments (정답 아님):
     · 서면-2026-법규재산-0119
     · 서면-2015-징세-0119
     · 기준-2023-법규부가-0044
     · 적부-국세청-2020-0119
   guardrail: "비슷한 문서를 정답으로 제시하지 말고, 사용자에게 '조회 실패'를 그대로 보고하세요."
```

0 패딩 차이(`0119` ↔ `119`)는 같은 문서로 본다(사이트가 4자리 0 패딩을 쓴다).
다만 정규화는 **조회용 후보 키**를 넓히는 데만 쓰고, 반환하는 문서번호는 언제나
사이트가 준 원문 문자열이다. 없는 번호를 만들지 않는다.

## 4. 키워드 검색 문법

사이트 검색 문법을 실제 요청으로 확정했다(세법해석 01~04 전체, 반환 건수).

| 입력 | 건수 | 의미 |
|---|---|---|
| `["상속"]` | 22,349 | 단일 낱말 |
| `["증여"]` | 22,924 | 단일 낱말 |
| `["상속","증여"]` | 14,913 | **AND** (배열 원소끼리) |
| `["상속 증여"]` | 14,913 | **AND** (원소 내부 공백) |
| `["상속|증여"]` | 30,360 | **OR** — `22,349 + 22,924 − 14,913 = 30,360` 정확히 일치 |
| `["상속"]` + 제외 `["증여"]` | 7,436 | **NOT** — `22,349 − 14,913 = 7,436` 정확히 일치 |

MCP 에서는 이렇게 쓴다.

```python
{"query": "상속 공동상속주택"}                  # AND
{"query": "상속 증여", "match": "any"}          # OR
{"query": "상속", "exclude": ["증여"]}          # NOT
{"query": '"공동상속주택 소수지분" 양도'}         # 따옴표로 묶으면 한 구절
```

**함정 두 가지** (실측):

- OR 는 **ASCII 파이프 `|`** 다. 문서에 자주 적히는 broken bar `¦`(U+00A6)는 OR 로
  동작하지 않고 AND 와 같은 결과를 준다.
- 정렬 필드에 허용되지 않는 값을 주면 오류가 아니라 **0건**이 온다
  (`RANK/DESC` → total 0, status SUCCESS). 이 서버는 실측 검증된
  `DCM_RGT_DTM` / `FRS_RGT_DTM` / `SCORE` 만 내보낸다.

## 9. 도구 (9개)

자료 종류마다 도구를 만들면 20~30개가 되어 모델이 선택을 헷갈린다. 도메인 파라미터
기반 통합 도구로 묶었다.

| 도구 | 용도 |
|---|---|
| `lookup_tax_document` | 문서번호 exact lookup (**문서번호를 알면 항상 이것 먼저**) |
| `search_tax_interpretations` | 세법해석례 검색 (사전답변·질의회신·과세기준자문·고시서면질의) |
| `search_tax_decisions` | 판례·결정례 검색 (과세적부·이의·심사·심판·판례·헌재) |
| `get_tax_document` | 문서 1건 본문·구조화 조회 (해석례/결정례 통합) |
| `search_tax_guidance` | 기본통칙·집행기준·고시·훈령 |
| `get_tax_guidance` | 통칙/집행기준 특정 조항 1건 |
| `search_tax_forms` | 법령서식·별표 |
| `search_taxlaw` | 영역 통합 검색 (어디를 볼지 모를 때의 진입점) |
| `tax_research` | 층별 근거 수집 (법률→…→통칙→집행기준→예규→불복→판례) |

> `get_tax_document` 는 권장안의 `get_tax_interpretation` / `get_tax_decision` 을
> 하나로 합친 것이다. 사이트 상세 조회 액션이 문서 종류와 무관하게 `ASIQTB002PR01`
> 하나이므로, 사용자가 '적부'가 결정례인지 해석례인지 알아야 할 이유가 없다.

## 10. 권위 층위 (authorityLevel)

세무 상담에서 가장 위험한 혼동은 **법적 근거와 안내자료를 같은 무게로 읽는 것**이다.
모든 응답에 층위를 붙인다.

| 값 | 의미 |
|---|---|
| `statute` / `enforcement_decree` / `enforcement_rule` | 법률 / 시행령 / 시행규칙 — 법적 구속력 |
| `nts_ruling` | 국세청 해석례(예규) — 과세관청의 법령해석, 법원을 구속하지 않음 |
| `nts_guidance` | 기본통칙·집행기준·고시·훈령 — 내부 집행기준, **법규 아님** |
| `adjudication` | 과세적부·이의신청·심사청구·심판청구 — 해당 사건에 대한 결정 |
| `court_case` | 법원 판례·헌재 결정 — 사법적 판단 |

## 11. 국세청 서버 장애 시 동작

**자료가 없는 것**과 **가져오지 못한 것**을 절대 섞지 않는다. 이 둘을 한 라벨로
뭉개면 장애가 부존재로 읽혀서, 실재하는 예규를 "없습니다"라고 답하는 거짓 부정이 된다.

| 오류 코드 | 의미 | 부존재 주장? |
|---|---|---|
| `NOT_FOUND` | 원본에 일치하는 자료가 없음 | **예** |
| `DETAIL_NOT_AVAILABLE` | 문서는 있으나 본문을 원본이 주지 않음 | 아니오 |
| `UPSTREAM_ERROR` | 국세청 오류·점검·비정상 응답 | 아니오 |
| `PARSE_ERROR` | 응답 형식이 예상과 다름 (사이트 개편 신호) | 아니오 |
| `RATE_LIMITED` | 이 서버의 자체 한도 초과 | 아니오 |
| `TIMEOUT` | 시간 초과 | 아니오 |
| `INVALID_INPUT` | 입력 오류 | 아니오 |

모든 오류에 `guardrail` 문구가 함께 실려, 모델이 본문·결론을 지어내지 못하게 한다.
점검 페이지(200 + HTML)와 빈 본문은 일시 장애로 보고 재시도한다.

## 12. rate limit 정책

국세법령정보시스템은 공개 조회 서비스이고 우리는 손님이다.

- **토큰버킷**: 기본 분당 60회, 버스트 20회. 고정창과 달리 연속 리필이라 창 초반에
  몰린 요청을 통째로 막지 않는다(`tax_research` 는 한 번에 5~8회를 호출한다).
- **캐시**: 검색 30분 / 문서 본문 24시간 / 통칙·집행기준·고시·훈령 12시간 /
  법령 목록 7일. 자료의 실제 갱신 특성에 맞춘 값이다.
- **동일 요청 병합**: 같은 키의 동시 요청은 하나로 합쳐 업스트림에 한 번만 나간다.
- **연결 재사용**: httpx keep-alive 풀.
- 재시도는 429/5xx 에만, 지수 백오프로 최대 3회.
